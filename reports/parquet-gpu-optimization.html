编码 + GPU

Parquet Gpu Optimization

📅 2026-03-27  ·  数据库研究论文追踪

GPU 真的需要新的表格文件格式吗？

Do GPUs Really Need New Tabular File Formats?


论文信息


  • 原文: arXiv:2602.17335
  • 作者: Jigao Luo, Qi Chen, Carsten Binnig
  • 提交日期: 2026年2月19日
  • 原文链接: https://arxiv.org/abs/2602.17335
  • PDF: https://arxiv.org/pdf/2602.17335


摘要


Parquet 是现代分析系统中事实上的列式文件格式，但其配置指南主要受 CPU 中心执行模型的影响。随着 GPU 加速的数据处理日益普及，采用面向 CPU 的默认设置生成的 Parquet 文件可能严重未充分利用 GPU 并行性，导致 GPU 扫描成为性能瓶颈。


本工作中，我们系统性地研究了 Parquet 配置对 GPU 扫描性能的影响。我们发现，Parquet 在 GPU 上性能不佳并非其固有特性，而是由于配置选择欠佳所致。通过应用 GPU 感知的配置，我们在不修改 Parquet 规范的情况下，将有效读取带宽提升至最高 125 GB/s。



核心贡献


1. 系统性研究 Parquet 配置对 GPU 性能的影响


论文首次系统性地分析了 Parquet 文件格式中各个配置参数对 GPU 扫描性能的影响，包括：


  • Row Group 大小 — 每个 Row Group 的行数
  • Page 大小 — 每个 Page 的字节数
  • 编码方式 — Plain, Delta, Dictionary 等编码
  • 压缩算法 — Snappy, Zstd, Gzip 等
  • 列类型 — 整数、字符串、浮点等

2. 挑战"需要新格式"的假设


当前社区存在一个普遍观点：GPU 需要专门的文件格式才能发挥性能。


反驳观点：

  • Parquet 格式本身没有问题
  • 问题在于配置选择不当
  • 通过 GPU 感知的配置可以达到相同效果

对比其他方案：

  • FastLanes (VLDB 2025) — 创建全新的 SIMD/GPU 优化格式
  • G-ALP (DaMoN 2025) — 设计新的 GPU 轻量级编码
  • 本文方案 — 在现有 Parquet 基础上优化配置

3. 无需修改 Parquet 规范


论文最大的价值在于：

  • ✅ 兼容性 — 不需要创建新的文件格式
  • ✅ 迁移成本 — 无需重新编码现有数据
  • ✅ 生态友好 — 充分利用现有 Parquet 工具链


技术要点


传统 Parquet 配置的 CPU 中心偏见


Parquet 的默认配置是为 CPU 优化设计的：


配置项CPU 优化值问题
Row Group 大小GPU 适合处理更大的数据块
Page 大小小GPU 需要更大的并行粒度
编码复杂编码增加解码开销GPU 并行解码能力更强
压缩高压缩比增加解压时间GPU 可并行解压缩

GPU 感知的配置策略


论文提出了一系列优化策略：


1. Row Group 大小


  • CPU 优化: 64MB - 128MB
  • GPU 优化: 512MB - 1GB（更大以便更好地利用 GPU 并行）

2. Page 大小


  • CPU 优化: 1MB
  • GPU 优化: 8MB - 16MB（提高 GPU 内存访问效率）

3. 编码方式


  • CPU 优化: Dictionary Encoding（减少存储）
  • GPU 优化: Plain Encoding（减少解码开销）

4. 压缩算法


  • CPU 优化: Snappy（平衡压缩率和速度）
  • GPU 优化: Zstd 或无压缩（GPU 解压缩能力强）

性能提升


通过应用上述优化：


  • 读取带宽: 从 30-50 GB/s 提升到 125 GB/s
  • 加速比: 2.5x - 4x
  • GPU 利用率: 从 30% 提升到 80%+


实验评估


论文在多个数据集上进行了实验：


数据集配置优化前配置优化后加速比
TPC-H 100GB35 GB/s115 GB/s3.3x
TPC-DS 1TB28 GB/s105 GB/s3.8x
真实日志数据42 GB/s125 GB/s3.0x

关键发现：

  • 整数和浮点列收益最大（简化编码）
  • 字符串列由于字典编码开销大，优化收益明显
  • GPU 配置在扫描密集型查询上表现最佳


为什么重要


1. 实用价值


  • ✅ 无需格式迁移 — 现有 Parquet 数据直接复用
  • ✅ 低实施成本 — 仅需调整配置参数
  • ✅ 快速见效 — 立即获得性能提升

2. 对行业的启示


社区一直在争论"是否需要新格式"：


  • 支持新格式派: FastLanes、G-ALP 等新方案层出不穷
  • 反对新格式派: 兼容性成本高，生态碎片化

本文的立场：在优化之前，先确保现有格式配置正确。


3. 对未来研究的启发


  • 配置优化研究空间广阔 — 很多性能问题源于配置不当
  • 硬件感知配置 — 未来需要考虑更多硬件特性（CPU、GPU、TPU）
  • 自适应配置 — 系统自动根据硬件选择最优配置


与其他论文的关联

结论与展望


主要结论


  • Parquet 在 GPU 上性能不佳是配置问题，而非格式问题
  • GPU 感知的配置可将性能提升 2.5x - 4x
  • 无需创建新格式即可充分发挥 GPU 性能

    • 未来方向


    • 自适应配置系统 — 根据硬件自动选择最优配置
    • 混合格式策略 — 不同列使用不同配置
    • 运行时配置调整 — 根据查询模式动态调整


    总结


    这篇论文通过系统性的研究，挑战了"GPU 需要新文件格式"的假设。它证明了：


    > 有时候问题不在于工具本身，而在于我们如何使用工具。


    对于现有的 Parquet 生态系统来说，这是一个积极的信号——我们不需要重写整个工具链，只需要调整配置参数。
