FastLanes: A SIMD/GPU-Optimized Columnar File Format

摘要


现代列式文件格式（如 Parquet）的设计目标是传统的 CPU 执行模型，未能充分利用现代硬件（SIMD 和 GPU）的并行能力。我们提出了 FastLanes，一个面向 SIMD/GPU 数据并行执行的新型开源列式文件格式。


FastLanes 的核心创新是灵活的表达式编码机制，支持轻量级和全数据并行编码的统一框架。通过级联压缩技术，FastLanes 在保持高压缩比的同时，实现了超过 100 亿整数/秒的解码吞吐量。


与 Parquet 相比，FastLanes 的压缩率高约 40%，解码速度快 5-10 倍。我们的开源实现完全兼容现有数据生态系统。



核心贡献


1. 灵活的表达式编码机制


传统编码的问题：

  • Parquet 使用固定的编码方案（Plain, Delta, Dictionary）
  • 编码方式选择基于启发式规则
  • 难以支持新的硬件（SIMD、GPU）

FastLanes 的创新：

  • 表达式编码 — 将编码表示为计算图
  • 灵活组合 — 多个编码可以组合使用
  • 硬件感知 — 编码选择考虑 SIMD/GPU 特性

2. 轻量级编码替代通用压缩


传统方法：

  • 数据编码 → Snappy/Zstd 压缩 → 存储
  • 解压流程：解压 Snappy/Zstd → 解码编码 → 查询

FastLanes 方法：

  • 直接使用轻量级编码（无需通用压缩）
  • 解码流程：直接解码 → 查询
  • 减少 50%+ 的解压开销

3. 级联压缩技术


FastLanes 支持多级编码级联：


原始数据
   ↓
编码 1 (例如 Delta)
   ↓
编码 2 (例如 Bit-packing)
   ↓
编码 3 (例如 RLE)
   ↓
存储

优势：

  • 每一级编码针对不同数据特征优化
  • 组合效果优于单一编码
  • 解码时并行执行多级解码

4. SIMD/GPU 友好的设计


特性SIMD 优化GPU 优化
向量操作256/512 位向量处理线程块并行
内存对齐缓存行对齐合并内存访问
分支友好最小化条件分支Warp 执行一致性
数据局部性L1/L2 缓存友好共享内存利用


编码机制


1. 表达式编码框架


FastLanes 将编码表示为有向无环图（DAG）：


[原始数据]
   ↓
[Delta 编码] → [位宽缩减] → [RLE 编码]
   ↓                            ↓
[字典编码]                  [行程展开]
   ↓                            ↓
        [并行解码输出]

优势：

  • 编码顺序可动态调整
  • 支持任意组合
  • 编译器可优化解码路径

2. 支持的编码类型


编码说明压缩率解码速度
Plain原始存储1.0x最快
Delta值增量编码1.5x - 2x快
RLE行程编码2x - 10x快（可并行）
Bit-packing多值打包1.5x - 3x快
Dictionary值去重2x - 20x中等
Prefix前缀共享2x - 5x快
FastPFor压缩整数3x - 8x中等
SIMD-BP128SIMD 位打包2x - 4x非常快

3. 自动编码选择


FastLanes 分析数据特征自动选择最优编码组合：


分析维度：

  • 值域范围（Min/Max）
  • 基数（唯一值数量）
  • 数据分布（均匀/偏斜）
  • 序列相关性（递增/递减/随机）

选择算法：

  • 遗传算法搜索编码组合空间
  • 目标函数：压缩率 × 解码速度权重
  • 约束：解码时间 < 阈值

4. 多列压缩 (MCC)


传统列式格式每列独立编码。FastLanes 支持多列联合编码：


  • 相关性利用 — 检测列间相关性
  • 联合位打包 — 多列打包到位
  • 共享字典 — 值域相似的列共享字典

示例：

  • 年份列 + 月份列 → 联合 RLE 编码
  • 类别 1 + 类别 2 → 联合字典编码

为什么重要


1. 重新定义文件格式设计目标


传统列式格式追求：

  • 高压缩率
  • 压缩/解压速度
  • CPU 友好

FastLanes 新增目标：

  • ✅ SIMD 并行性 — 256/512 位向量处理
  • ✅ GPU 友好 — 大规模并行解码
  • ✅ 表达式编码 — 灵活的编码组合

2. 挑战 Parquet 的统治地位


Parquet 是事实标准，但有局限性：


局限性说明FastLanes 解决方案
CPU 中心设计未优化 SIMD/GPU表达式编码支持硬件感知选择
固定编码方案难以扩展新编码灵活的表达式框架
解码慢于查询扫描成为瓶颈超过 100 亿/秒解码吞吐

3. 兼容现有生态系统


FastLanes 开源并兼容：

  • ✅ 与 Parquet 互转
  • ✅ 兼容 Arrow 内存格式
  • ✅ 支持 Spark/Flink 等框架


技术实现


编码流水线


1. 数据分析阶段
   - 扫描数据样本
   - 分析数据特征
   - 选择编码组合

2. 编码阶段
   - 应用表达式编码
   - 级联多级编码
   - 生成元数据

3. 压缩阶段
   - 轻量级后处理压缩
   - 生成索引

4. 存储阶段
   - 写入 FastLanes 文件
   - 更新统计信息

解码流水线


1. 文件读取
   - 读取元数据
   - 定位数据块

2. 并行解码
   - SIMD 向量解码（CPU）
   或
   - GPU 块解码（GPU）

3. 数据转换
   - 转换为目标格式（Arrow/Parquet）
   - 传递给查询引擎

关键洞察


1. 表达式编码 > 固定编码


传统格式选择编码基于启发式规则：


if cardinality < 1000:
    use DictionaryEncoding()
else:
    use PlainEncoding()

FastLanes 使用表达式编码：


encoding = DeltaEncoding() + BitPacking() + RLEEncoding()

优势：组合编码效果优于单一编码。


2. SIMD/GPU 友好是第一优先级


传统格式权衡压缩率和解码速度。FastLanes 优先考虑：


  • 并行解码能力 — SIMD 向量操作
  • GPU 内存访问 — 合并读/写
  • 分支可预测性 — Warp 一致执行

3. 轻量级编码 > 通用压缩


通用压缩（Snappy、Zstd）：

  • ✅ 高压缩率
  • ❌ 顺序解码（难以并行）
  • ❌ 分支密集（不利于 SIMD/GPU）

轻量级编码（RLE、Bit-packing）：

  • ✅ 可并行解码
  • ✅ 分支稀疏
  • ✅ SIMD/GPU 友好


未来方向


1. 更多编码类型


  • Delta of Delta — 递增数据的进一步压缩
  • Frame of Reference — 基于参考值的编码
  • Mixed Integer/Float — 联合编码浮点和整数

2. 自适应编码选择


  • 运行时重新编码
  • 查询模式感知
  • 学习型编码推荐

3. 硬件多样性支持


  • ARM NEON 支持
  • AVX-512 优化
  • Apple Silicon 优化

4. 跨格式互操作


  • 与 Parquet/ORC 双向转换
  • 与 Arrow 内存格式零拷贝互操作
  • 与 Spark/Flink 深度集成


结论


FastLanes 重新定义了列式文件格式的设计目标：


  • 表达式编码框架 — 灵活的编码组合
  • SIMD/GPU 友好 — 超过 100 亿/秒解码吞吐
  • 级联压缩 — 压缩率比 Parquet 高 40%
  • 开源兼容 — 可与现有生态无缝集成

    • FastLanes 证明：创建新格式比优化现有格式更能充分发挥现代硬件能力。
