一、从马尔可夫决策过程到动作分布学习


机器人控制的核心任务是学习一个策略 $\pi_\theta(a_t | o_t, g)$，其中：

  • $o_t$：当前观测（视觉图像 + 机器人状态）
  • $g$：语言指令目标（可选）
  • $a_t$：当前动作（末端位姿、关节角、夹爪开合等）

传统方法如 Behavior Cloning（行为克隆）直接用 MSE 回归动作：


$$\mathcal{L}_{\text{MSE}} = \mathbb{E}_{t, (o,a) \sim \mathcal{D}} \|a_t - \hat{a}_\theta(o_t, g)\|^2$$


问题所在：

  • 动作空间高维（通常 7~14 维），MSE 优化困难
  • 同一指令可能有多条合理动作路径（多模态），MSE 只能学到均值
  • 离群动作（夹爪突然张开、避障急停）会被平均效应抹平

    • 扩散模型的思想恰好解决了这些问题——它不直接回归动作，而是学习把噪声"去噪"成动作。



    二、DDPM 数学体系


    2.1 前向扩散过程（Forward Process）


    给定真实动作 $a_0 \sim q(a_0)$，定义 $T$ 步前向扩散：


    $$q(a_t | a_{t-1}) = \mathcal{N}\left(a_t; \sqrt{1 - \beta_t} a_{t-1}, \beta_t I\right)$$


    其中 $\{\beta_t\}_{t=1}^T$ 是预定义的噪声调度（noise schedule）。


    经过闭合推导，任意时间步 $t$ 的分布可以直接写为：


    $$q(a_t | a_0) = \mathcal{N}\left(a_t; \sqrt{\bar{\alpha}_t} a_0, (1 - \bar{\alpha}_t) I\right)$$


    其中：

    $$\alpha_t = 1 - \beta_t, \quad \bar{\alpha}_t = \prod_{i=1}^t \alpha_i$$


    直观理解：随着 $t$ 增大，$\bar{\alpha}_t \to 0$，$a_t$ 逐渐变成纯噪声。当 $T$ 足够大（通常 100~1000），$a_T \approx \mathcal{N}(0, I)$。


    2.2 反向过程（Reverse Process）


    我们训练一个噪声预测网络 $\epsilon_\theta(a_t, c, t)$，其中 $c$ 是条件信息（观测 $o$ 和目标 $g$），$t$ 是时间步嵌入。网络学习预测注入的噪声 $\epsilon$。


    训练损失函数：


    $$\mathcal{L} = \mathbb{E}_{t, \epsilon, a_0, c} \left[ \|\epsilon - \epsilon_\theta(\sqrt{\bar{\alpha}_t} a_0 + \sqrt{1 - \bar{\alpha}_t} \epsilon, c, t)\|^2 \right]$$


    > 注意：这是 L2 Loss。我们稍后在第三篇会详细分析为什么 L1/L2 的选择在机器人控制中至关重要。


    2.3 推理：迭代去噪


    从纯噪声 $a_T \sim \mathcal{N}(0, I)$ 开始，依次采样：


    $$a_{t-1} = \frac{1}{\sqrt{\alpha_t}}\left(a_t - \frac{1 - \alpha_t}{\sqrt{1 - \bar{\alpha}_t}} \epsilon_\theta(a_t, c, t)\right) + \sigma_t z$$


    其中 $z \sim \mathcal{N}(0, I)$，$\sigma_t$ 是与 $\beta_t$ 相关的噪声项。


    这个过程叫 DDPM（Denoising Diffusion Probabilistic Models） 采样，每步需要完整的前向网络推理，$T$ 通常为 100~1000 步，直接用于机器人实时控制是不可能的。



    三、DDIM：把 100 步压到 10 步


    DDIM（Denoising Diffusion Implicit Models） 的核心洞察是：DDPM 的随机性并非必要。DDIM 定义了一个确定性的采样轨迹：


    $$a_{t-1} = \sqrt{\bar{\alpha}_{t-1}} \cdot \underbrace{\frac{a_t - \sqrt{1 - \bar{\alpha}_t} \epsilon_\theta(a_t, c, t)}{\sqrt{\bar{\alpha}_t}}}_{\text{predicted } a_0} + \sqrt{1 - \bar{\alpha}_{t-1}} \cdot \underbrace{\epsilon_\theta(a_t, c, t)}_{\text{predicted noise}}$$


    DDIM 可以将采样步数从 100 降到 10~20 步，速度提升 5~10 倍，精度损失很小。


    比赛中的实际建议：

    • 推理时先用 DDIM-10 或 DDIM-20 测试
    • 如果任务需要更高精度动作（如精细抓取），可以用 DDIM-50
    • $\eta$ 参数控制随机性：$\eta=0$ 时完全确定性，$\eta=1$ 时接近 DDPM


    四、Flow Matching：2025 年主流范式


    4.1 什么是 Flow Matching？


    Flow Matching（FM）是一种更简洁的扩散式生成建模框架，省去了 DDPM 的复杂噪声调度推导。


    核心思想：直接在起点（噪声 $x_1$）和终点（数据 $x_0$）之间定义一个常微分方程（ODE）路径：


    $$x_t = (1 - t) \cdot x_1 + t \cdot x_0, \quad t \in [0, 1]$$


    训练时，给定 $x_0$ 和噪声 $x_1$，构造中间样本 $x_t$：


    $$x_t = (1 - t) x_1 + t x_0$$


    预测目标改为 速度场（velocity） $\mathbf{v}_\theta(x_t, c, t)$：


    $$\mathcal{L}_{\text{FM}} = \mathbb{E}_{t, x_0, x_1, c} \| \mathbf{v} - \mathbf{v}_\theta(x_t, c, t) \|^2$$


    其中真实速度场是：


    $$\mathbf{v} = x_0 - x_1$$


    4.2 为什么 Flow Matching 成为 2025 年主流？


    对比维度DDPMFlow Matching
    采样步数100~1000 步（慢）10~50 步（快）
    理论基础变分推断（复杂）最优传输（简洁）
    轨迹分布随机可可控（ODE）
    2025 年主流采用逐渐退出GR00T-N1, π0, GO-1 等都在用
    与 LLM 架构兼容性一般更好（统一建模）

    GR00T-N1（NVIDIA 2025.03）明确使用 Flow Matching 作为 Action Head：

    Observation → SigLIP + Language Encoder → Feature Concatenation
           → DiT (Diffusion Transformer) with Flow Matching Head
           → 输出动作序列

    π0（Physical Intelligence 2024.10）同样基于 Flow Matching 构建。


    4.3 Flow Matching 的采样


    Flow Matching 的采样通过求解 ODE 完成：


    $$\frac{dx}{dt} = -\mathbf{v}_\theta(x, c, t)$$


    使用简单的 Euler 或 RK4 积分即可。步数通常 10~20 步即可达到满意质量。



    五、条件引导：让机器人"听话"


    5.1 Classifier-Free Guidance（CFG）


    CFG 是让扩散模型在推理时同时使用条件信息（观测、指令）的关键技术。


    训练阶段：

    • 以一定概率 $p$（通常 10~20%）将条件 $c$ 替换为 NULL（空条件）
    • 网络同时学习有条件和无条件去噪

    推理阶段：通过线性外推放大条件信号：


    $$\tilde{\epsilon}_\theta(a_t, c, t) = (1 + w) \cdot \epsilon_\theta(a_t, c, t) - w \cdot \epsilon_\theta(a_t, \emptyset, t)$$


    其中 $w \in [0, \infty)$ 是 引导强度（guidance scale）：

    • $w = 0$：无引导，生成多样但可能偏离指令
    • $w = 0.5 \sim 1.5$：标准范围，条件对齐好
    • $w > 2$：强引导，动作更精确但可能缺乏多样性

    > 比赛调参建议：$w$ 是最值得优先调节的超参数。通常 0.75~1.5 之间是安全区间。


    5.2 无分类器引导在机器人控制中的特殊价值


    机器人动作的真实分布是多模态的——同一个"把杯子放到碗里"指令，可以从左侧放、右侧放、先抬再放等。CFG 允许模型在指令精确性和动作多样性之间做权衡。



    六、2025 年关键架构改进一览


    6.1 从 U-Net 到 DiT（Diffusion Transformer）


    传统 Diffusion Policy（如 CDNA, DAL）使用 U-Net 作为噪声预测网络。2024-2025 年主流工作全面转向 DiT（Diffusion Transformer）：


    • DiT 的优势：序列建模能力强，更容易与 LLM/VLM 架构融合
    • 代表作：GR00T-N1、π0、GO-1 都使用 DiT-style Action Head

    6.2 动作分词器（Action Tokenizer）


    FAST（Physical Intelligence, 2025.01）是这个方向的里程碑：


    核心思想：用 DCT（离散余弦变换） 把连续动作序列编码为离散 token：


    连续动作 [a_1, a_2, ..., a_N]（N=16~64）
    → DCT 变换 → 频域表示
    → 量化 → 离散 token 序列

    这样做的好处：

  • 可以用 LLM-style 的 next-token prediction 来训练动作模型
  • 训练速度提升 5 倍（vs 原始连续动作扩散训练）
  • tokenize 后的动作可以跨任务复用

    • π0-FAST 就是用这个思想训练的。


    6.3 两阶段训练 vs 端到端训练


    范式代表工作特点
    两阶段GO-1 (ViLLA)先训 VLM 视觉-语言，再冻住 VLM 训练 Action Head
    端到端π0, GR00T-N1VLM + Action 一起训练，梯度流畅但需要更多数据
    混合OpenVLA预训练 VLM + 轻量 Action Adapter，平衡效率和性能

    比赛建议：如果你的数据集规模有限（< 10 万条轨迹），优先选择 两阶段 + 冻住 VLM；数据量充足时可以尝试端到端。



    七、实践：如何在代码里实现一个基础 Diffusion Policy


    import torch
import torch.nn as nn
import math

class SimpleDiffusionPolicy(nn.Module):
    """
    最简版 Diffusion Policy（DDPM 训练 + DDIM 推理）
    仅供理解原理使用，不适合直接上场比赛
    """
    def __init__(self, obs_dim=128, action_dim=7, hidden=256, T=100):
        super().__init__()
        self.T = T
        self.action_dim = action_dim
        
        # 噪声预测网络（MLP 版本，实际推荐 DiT）
        self.noise_pred_net = nn.Sequential(
            nn.Linear(obs_dim + action_dim + 1, hidden),  # obs + action + time
            nn.SiLU(),
            nn.Linear(hidden, hidden),
            nn.SiLU(),
            nn.Linear(hidden, action_dim)
        )
        
        # 噪声调度
        self.register_buffer('betas', self._cosine_beta_schedule(T))
        alphas = 1.0 - self.betas
        self.register_buffer('alphas_bar', torch.cumprod(alphas, dim=0))

    def _cosine_beta_schedule(self, T, s=0.008):
        """Cosine schedule，比 linear schedule 更稳定"""
        steps = torch.arange(T + 1)
        alphas = torch.cos((steps / T + s) / (1 + s) * math.pi * 0.5) ** 2
        alphas = alphas / alphas[0]
        betas = 1 - alphas[1:] / alphas[:-1]
        return torch.clip(betas, 0.0001, 0.02)

    def forward(self, obs, action_noisy, t):
        """训练：预测噪声"""
        # t 是归一化的时间步 [0, 1]
        x = torch.cat([obs, action_noisy, t], dim=-1)
        return self.noise_pred_net(x)

    @torch.no_grad()
    def sample(self, obs, num_steps=20):
        """推理：DDIM 采样"""
        batch_size = obs.shape[0]
        a_t = torch.randn(batch_size, self.action_dim, device=obs.device)
        
        # 时间步从 T 倒数到 0
        timesteps = torch.linspace(self.T, 0, num_steps, device=obs.device).long()
        
        for i in range(num_steps - 1):
            t = timesteps[i]
            t_next = timesteps[i + 1]
            
            # 预测噪声
            eps = self.forward(obs, a_t, (t / self.T).expand(a_t.shape[0]))
            
            # DDIM 更新（简化版）
            alpha_bar_t = self.alphas_bar[t]
            alpha_bar_t_next = self.alphas_bar[t_next]
            
            a_t = (a_t - torch.sqrt(1 - alpha_bar_t) * eps) / torch.sqrt(alpha_bar_t)
            a_t = torch.sqrt(alpha_bar_t_next) * a_t + \
                  torch.sqrt(1 - alpha_bar_t_next) * eps
        
        return a_t  # 最终动作


    八、本篇要点总结


    知识点关键结论
