一、为什么需要 Action Chunking？


1.1 自回归模型的误差累积问题


传统的单步预测策略（每步预测一个动作）有一个根本缺陷：误差累积。


假设机器人有 1% 的概率在单步预测中出错：


预测步数累积正确率
1 步99.0%
10 步90.4%
50 步60.5%
100 步36.6%

到了 100 步，误差已经累积到不可接受的程度。


1.2 Action Chunking 的核心思想


一次预测 $K$ 步动作，而非单步动作：


自回归（单步）：a₁ → a₂ → a₃ → ... （误差累积）
Action Chunking：[a₁, a₂, ..., a_K] ← 一次预测！（chunk 内无累积误差）

在 chunk 内部，所有动作是一次性生成的，不存在步步预测的误差传播问题。


1.3 Chunk 内动作一致性的数学保证


Action Chunking 的 chunk 内部动作一致性来源于扩散模型本身的联合分布建模：


$$\text{一次预测 } [a_1, a_2, ..., a_K] \sim p_\theta([a_1, ..., a_K] | o)$$


这等价于直接建模整条轨迹的联合分布，而非自回归分解：


$$p(a_1, ..., a_K | o) = p(a_1 | o) \cdot p(a_2 | o, a_1) \cdot p(a_3 | o, a_1, a_2) \cdots$$


自回归分解的问题是：越到后面的动作，条件越多，信息衰减越严重。



二、Chunk Size 的选择


2.1 常见 Chunk Size 对比


Chunk Size步数（@10Hz）适用场景优缺点
K = 80.8 秒极短任务、精细操作计算量低，规划视野短
K = 161.6 秒单步操作（抓取、放置）通用推荐起始值
K = 323.2 秒短时序任务平衡视野和计算
K = 646.4 秒中等时序任务视野好，计算量适中
K = 12812.8 秒长时序任务视野极好，训练困难
K = 256+25+ 秒复杂长任务仅适用于 π0.5 等大模型

2.2 Chunk Size 与任务长度的关系


经验法则：Chunk Size 应该至少覆盖任务的 70% 动作时长。


任务：把杯子从 A 点放到 B 点
预估动作时长：约 3 秒（30 步 @10Hz）
建议 Chunk Size：32~64（1.5x~2x 覆盖）

2.3 Chunk Size 与训练稳定性


大 Chunk 的训练挑战：


  • 高维输出空间：K=64, action_dim=14 → 输出 64×14=896 维
  • 内存消耗：chunk 越大，中间激活值越大，GPU 显存压力越大
  • 训练不稳定：chunk 内多模态分布更难建模

    • 缓解方案：使用 Gradient Checkpointing（激活重计算，用时间换显存）


    from torch.utils.checkpoint import checkpoint_sequential

class ChunkDiffusionModel(nn.Module):
    def __init__(self, chunk_size=64, action_dim=14):
        super().__init__()
        self.chunk_size = chunk_size
        self.dit = checkpoint_sequential(
            DitBlocks(num_layers=12),
            segments=4,  # 分成4段，每段单独算梯度，节省显存
            input
        )


    三、Observation Chunking：历史观测的利用


    3.1 观测历史的必要性


    机器人的当前决策依赖于历史上下文：

    • 物体在运动中（需要知道过去位置才能预测未来）
    • 上一帧夹爪是否合上（影响下一步抓取决策）
    • 关节是否有碰撞趋势（需要速度信息才能判断）

    没有历史观测的模型是短视的，无法处理动态场景。


    3.2 Observation Chunk 的实现


    class ObservationHistoryEncoder(nn.Module):
    """
    观测历史编码器：将最近 K 帧观测编码为上下文向量
    """
    def __init__(self, obs_dim=128, hidden=512, history_len=8):
        super().__init__()
        self.history_len = history_len
        
        self.frame_encoder = nn.Sequential(
            nn.Linear(obs_dim, hidden),
            nn.GELU(),
            nn.Linear(hidden, hidden)
        )
        
        # 时序聚合用 Transformer，而非 RNN
        self.temporal_aggregator = nn.TransformerEncoder(
            nn.TransformerEncoderLayer(
                d_model=hidden, nhead=8,
                dim_feedforward=hidden * 4,
                batch_first=True
            ),
            num_layers=4
        )
        
        self.pos_enc = PositionalEncoding(hidden)
    
    def forward(self, obs_history):
        """
        Args:
            obs_history: [batch, history_len, obs_dim]（最近 history_len 帧）
        """
        x = self.frame_encoder(obs_history)
        x = x + self.pos_enc(x)
        temporal_context = self.temporal_aggregator(x)
        current_obs = temporal_context[:, -1, :]  # 用最后一帧作为当前上下文
        return current_obs

    四、DiT vs U-Net：为什么 Transformer 更适合时序建模


    4.1 U-Net 在时序建模上的局限


    U-Net 的核心是卷积 + Skip Connection，擅长建模空间层次结构（图像局部→全局），但对时序依赖建模能力弱——某一步动作只能看到附近的动作，视野受限。


    4.2 DiT 的时序优势


    维度U-NetDiT
    时序依赖范围局部（逐层扩大）全局（一步到位）
    Chunk SizeK ≤ 32（否则不稳定）K ≥ 64（天然支持长 chunk）
    动作序列一致性弱（逐帧独立注入噪声）强（所有动作 token 联合去噪）
    与 VLM 架构融合需要 adapter直接拼接/共享 embedding

    class ActionDiT(nn.Module):
    """
    用于机器人动作的 DiT（Diffusion Transformer）
    """
    def __init__(self, action_dim=14, chunk_size=64,
                 model_dim=768, num_heads=12, num_layers=12):
        super().__init__()
        self.action_embed = nn.Linear(action_dim, model_dim)
        self.t_embed = TimestepEmbedder(model_dim)
        self.cond_proj = nn.Linear(2048, model_dim)  # VLM 特征
        
        self.blocks = nn.ModuleList([
            DiTBlock(model_dim=model_dim, num_heads=num_heads)
            for _ in range(num_layers)
        ])
        
        self.norm_final = nn.LayerNorm(model_dim)
        self.head = nn.Linear(model_dim, action_dim)
    
    def forward(self, noisy_action_chunk, obs_cond, lang_cond, t):
        B, K, D = noisy_action_chunk.shape
        x = self.action_embed(noisy_action_chunk)
        x = x + self.t_embed(t).unsqueeze(1)
        cond_emb = self.cond_proj(torch.cat([obs_cond, lang_cond], dim=-1))
        for block in self.blocks:
            x = block(x, cond_emb)
        return self.head(self.norm_final(x))


    五、时序平滑与动作去噪技巧


    5.1 Temporal Ensemble（时序集成）


    每次推理时生成 $N$ 个候选 chunk，然后加权平均：


    @torch.no_grad()
def temporal_ensemble_sample(model, obs, lang, num_candidates=4):
    candidates = []
    for i in range(num_candidates):
        torch.manual_seed(42 + i)
        action_chunk = cfg_sample(model, obs, lang, w=1.0)
        candidates.append(action_chunk)
    
    candidates = torch.stack(candidates)
    # 中间动作权重更高（两端受边界噪声影响更大）
    weights = torch.linspace(0.5, 1.0, candidates.shape[2], device=candidates.device)
    weights = weights / weights.sum()
    
    smooth_chunk = (candidates * weights[None, None, :, None]).sum(dim=2)
    return smooth_chunk

    5.2 EMA（指数移动平均）


    训练时用 EMA 权重更新，推理时用 EMA 模型，几乎无额外计算成本：


    class EMA:
    def __init__(self, model, decay=0.9999):
        self.model = model
        self.decay = decay
        self.shadow = {name: p.data.clone()
                       for name, p in model.named_parameters() if p.requires_grad}
    
    def update(self):
        for name, param in self.model.named_parameters():
            if param.requires_grad:
                self.shadow[name] = (1 - self.decay) * param.data + \
                                    self.decay * self.shadow[name]
    
    def apply_shadow(self):
        """推理时用 EMA 权重"""
        for name, param in self.model.named_parameters():
            if param.requires_grad:
                param.data = self.shadow[name]

    5.3 Savitzky-Golay 滤波


    from scipy.signal import savgol_filter

def smooth_action_sequence(action_seq, window_length=5, polyorder=2):
    """Savitzky-Golay 滤波：去除高频抖动"""
    # action_seq: [batch, chunk, action_dim]
    smoothed = np.zeros_like(action_seq)
    for b in range(action_seq.shape[0]):
        for d in range(action_seq.shape[2]):
            if action_seq.shape[1] >= window_length:
                smoothed[b, :, d] = savgol_filter(
                    action_seq[b, :, d],
                    window_length=window_length,
                    polyorder=polyorder
                )
    return torch.from_numpy(smoothed).float()


    六、比赛实战建议


    6.1 Chunk Size 选择路线图


    任务时长 ≤ 1.6 秒        → action_chunk = 16
1.6 秒 < 任务时长 ≤ 3.2 秒 → action_chunk = 32
3.2 秒 < 任务时长 ≤ 6.4 秒 → action_chunk = 64（推荐 DiT）
任务时长 > 6.4 秒        → action_chunk = 128 + ACT/MST

    6.2 长时序任务专项建议


    以下情况说明你需要长 Chunk / 强时序建模：

    • [ ] 单次任务超过 3 秒（> 30 步 @ 10Hz）
    • [ ] 任务有明显的子目标序列（A→B→C→D）
    • [ ] 早期决策会影响后期（"先开盖再抓取"）
    • [ ] 观测有延迟（相机延迟、控制延迟）

    七、本篇要点总结


    知识点关键结论
    Action Chunking 优势消除自回归误差累积，一次生成多条连贯动作
    Chunk Size 选择16~64 通用，K ≥ 64 时建议用 DiT 替代 U-Net
    Observation Chunk历史帧数 = chunk 内早期步数，保持时序对齐
    DiT vs U-NetDiT 全局感受野，时序建模能力强，适合大 chunk
    Temporal Ensemble多个候选 chunk 平均，可减少 10~20% 动作抖动
    EMA推理用 EMA 模型，几乎无额外计算，显著平滑
    Savitzky-Golay事后滤波，适合需要亚毫秒级平滑的精细操作
