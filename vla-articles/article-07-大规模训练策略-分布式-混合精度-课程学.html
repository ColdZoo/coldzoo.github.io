一、分布式训练的三种范式


1.1 数据并行（Data Parallelism, DP）


最简单也最常用的方法：


GPU 0: batch 0~127      →  forward → backward → grad_0
GPU 1: batch 128~255    →  forward → backward → grad_1
GPU 2: batch 256~383    →  forward → backward → grad_2
GPU 3: batch 384~511    →  forward → backward → grad_3
                                    ↓
                            AllReduce (梯度平均)
                                    ↓
                            optimizer step (每个 GPU 独立执行)

优点：实现简单，效果好，几乎线性加速

缺点：每个 GPU 都要完整模型，显存瓶颈依然存在


1.2 模型并行（Model Parallelism, MP）


把模型拆分到多个 GPU：


GPU 0: VLM backbone (2B params)
GPU 1: Action Head (500M params)
         ↓ 张量重排（all-reduce needed）

缺点：GPU 间通信开销大，效率低，复杂


1.3 ZeRO-3（DeepSpeed）——推荐方案


ZeRO（Zero Redundancy Optimizer）将优化器状态、梯度、模型参数分片到不同 GPU：


Stage分片内容通信量显存节省
ZeRO-1优化器状态分片少~4x
ZeRO-2+ 梯度分片中等~8x
ZeRO-3+ 模型参数分片多~N倍（N=GPU数）

ZeRO-3 让每个 GPU 只存储 1/N 的模型参数，需要时通过 All-Gather 获取其他分片。


推荐配置（8 GPU 训练 3B 模型）：


# deepspeed_config.json
{
    "zero_optimization": {
        "stage": 3,
        "offload_optimizer": {
            "device": "cpu",      # CPU offload 优化器状态，进一步省显存
            "pin_memory": true
        },
        "offload_param": {
            "device": "cpu",      # CPU offload 参数（极端情况）
            "pin_memory": true
        },
        "overlap_comm": true,     # 重叠通信和计算
        "contiguous_gradients": true,
        "reduce_bucket_size": 1e8,
        "stage3_gather_16bit_weights_on_model_save": true
    },
    "bf16": {"enabled": true},   # 混合精度
    "gradient_clipping": 1.0,
    "gradient_accumulation_steps": 4,
    "train_batch_size": 256,
    "train_micro_batch_size_per_gpu": 8

1.4 FSDP（Fully Sharded Data Parallel）——PyTorch 原生方案


FSDP 是 PyTorch 原生的 ZeRO-3 实现，比 DeepSpeed 集成更紧密：


# 使用 PyTorch FSDP
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP
from torch.distributed.fsdp import ShardingStrategy, MixedPrecision
from torch.distributed.fsdp.wrap import transformer_auto_wrap_policy

# 混合精度配置
mp_policy = MixedPrecision(
    param_dtype=torch.bfloat16,
    reduce_dtype=torch.float32,    # AllReduce 用 FP32
    buffer_dtype=torch.bfloat16,
)

# 自动 wrap 策略（Transformer 层自动分片）
model = FSDP(
    base_model,
    sharding_strategy=ShardingStrategy.FULL_SHARD,
    mixed_precision=mp_policy,
    auto_wrap_policy=transformer_auto_wrap_policy,
    device_id=torch.cuda.current_device(),
)

# 训练循环
for batch in dataloader:
    with FSDP.autocast():
        output = model(batch)
        loss = compute_loss(output)
    
    model.backward(loss)  # 自动分片梯度
    model.step()


二、混合精度训练：FP8 vs BF16 vs FP32


2.1 精度选择指南


精度显存占用数值稳定性支持硬件建议
FP321x最稳定所有 GPU主梯度存 FP32
BF16~0.5x好Ampere+ (A100/H100)首选，精度-效率平衡最好
FP16~0.5x一般所有 GPU容易溢出，不推荐
FP8~0.25x较差H100 only极端省显存用

2.2 BF16 混合精度详解


BF16（Brain Float 16）的指数位比 FP16 多，数值范围更大，训练更稳定：


FP16: 1 sign + 5 exp + 10 mantissa（范围 ~6e-5 ~ 65504）
BF16: 1 sign + 8 exp + 7 mantissa（范围 ~9e-10 ~ 3e38）

为什么 BF16 更适合大模型训练：

  • BF16 指数范围接近 FP32，梯度计算不容易溢出
  • 显存减半，通信带宽减半
  • 几乎无精度损失

2.3 BF16 混合精度训练代码


# PyTorch 原生 BF16 混合精度
from torch.cuda.amp import autocast, GradScaler

scaler = GradScaler('cuda', init_scale=65536.0)

for batch in dataloader:
    # Forward 用 BF16
    with autocast(dtype=torch.bfloat16):
        output = model(batch)
        loss = compute_loss(output)
    
    # Backward 用 GradScaler
    scaler.scale(loss).backward()
    
    # 梯度裁剪
    scaler.unscale_(optimizer)
    torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
    
    # Optimizer step
    scaler.step(optimizer)
    scaler.update()

三、梯度累积：如何在有限显存下训练大批量


3.1 原理


当单个 GPU 的显存不够放下 batch_size=256 时，可以分 micro_batch_size=8 次做前向/反向计算，累积梯度：


micro_batch_1: loss.backward() → grad_acc += grad_1
micro_batch_2: loss.backward() → grad_acc += grad_2
...
micro_batch_32: loss.backward() → grad_acc += grad_32
                        ↓
                   optimizer.step()  # 等累积完再更新
                   grad_acc.zero_()  # 清零，准备下一轮

逻辑 batch_size = micro_batch_size × gradient_accumulation_steps × num_gpus


3.2 配置建议


总 batch_sizenum_gpusmicro_batchaccum_steps

注意：accum_steps 增大会让训练变慢，但 batch_size 增大通常能提升最终效果——存在一个 sweet spot。



四、课程学习（Curriculum Learning）


4.1 核心思想


课程学习让模型从简单到复杂逐步学习——这比随机打乱数据训练更高效：


阶段 1（简单）：单步操作、短轨迹、低干扰
阶段 2（中等）：多步操作、中等轨迹
阶段 3（复杂）：长时序、高干扰、未知场景

4.2 机器人控制的课程设计


class RobotCurriculum:
    """
    机器人数据的课程学习调度器
    """
    def __init__(self, total_steps):
        self.total_steps = total_steps
        
        # 定义难度维度
        self.difficulty_dims = {
            'trajectory_length': {'min': 10, 'max': 200},
            'num_objects': {'min': 1, 'max': 5},
            'collision_risk': {'min': 0.0, 'max': 1.0},
            'instruction_complexity': {'min': 0.0, 'max': 1.0},
        }
    
    def get_difficulty_weight(self, step):
        """
        返回各难度维度的权重（step=0 简单，step=total 复杂）
        """
        progress = step / self.total_steps
        
        # 使用余弦退火到复杂
        weight = 0.5 * (1 - math.cos(math.pi * progress))
        
        return {
            'trajectory_length': self.lerp(
                self.difficulty_dims['trajectory_length']['min'],
                self.difficulty_dims['trajectory_length']['max'],
                weight
            ),
            'num_objects': self.lerp(
                self.difficulty_dims['num_objects']['min'],
                self.difficulty_dims['num_objects']['max'],
                weight
            ),
            'collision_risk': self.lerp(0.0, 1.0, weight),
        }
    
    def lerp(self, a, b, t):
        return a + (b - a) * t
    
    def filter_batch(self, batch, step):
        """根据当前课程阶段过滤/加权 batch"""
        weights = self.get_difficulty_weight(step)
        
        # 计算每个样本的难度分数
        difficulty_scores = self.compute_difficulty_scores(batch)
        
        # 采样权重：简单样本权重低，复杂样本权重高（课程阶段）
        # 注意：不是丢弃简单样本，而是降低其权重
        weights_per_sample = torch.tensor([
            self.score_to_weight(ds, step)
            for ds in difficulty_scores
        ])
        
        # 归一化
        weights_per_sample = weights_per_sample / weights_per_sample.sum()
        
        # 加权采样
        indices = torch.multinomial(weights_per_sample, batch_size, replacement=False)
        return batch[indices]

4.3 课程学习的三大策略


策略做法适用场景
难度过滤早期只训练简单样本，忽略复杂样本数据充足，模型容量大
难度加权所有样本都训练，但简单样本权重低、复杂样本权重高数据不充足，不想浪费数据
难度混合每个 batch 包含不同难度的样本，比例随训练变化通用推荐

4.4 GO-1 的课程学习设计


GO-1 实际上采用了两阶段课程：

  • Stage 1：在高质量真机数据（AgiBot World-Alpha）上训练，这些数据轨迹短、噪声低、任务简单
  • Stage 2：混入大规模视频数据（AgiBot World-Beta），这些数据包含更多样的场景和更长的任务

    • 这本质上也是一种课程——从简单真机数据到复杂异构数据。

    5.3 冻结策略对比


    策略做法优点缺点
    冻住 VLM只训练 Action Head防止 VLM 灾难性遗忘，数据效率高VLM 和 Action 特征可能不对齐
    全部放开端到端训练特征对齐最好需要更多数据，容易过拟合
    渐进放开先冻住，后逐步解冻平衡两者实现复杂

    比赛建议：

    • 数据 < 10 万条 → 冻住 VLM
    • 数据 10~50 万条 → 冻住 VLM + LoRA adapter
    • 数据 > 50 万条 → 端到端训练

    八、本篇要点总结


    知识点关键结论
    ZeRO-3 vs FSDPZeRO-3 省显存强，FSDP 集成更紧，首选看团队熟悉度
    BF16 > FP16BF16 指数位多，训练稳定，H100/A100 推荐用 BF16
    梯度累积effective_batch_size = micro × accum × num_gpus
    课程学习从简单到复杂，余弦退火难度权重
    预训练-微调预训练学隐动作语义，微调学具体动作映射
    冻住策略数据少冻 VLM，数据多端到端
    EMA几乎无成本，推理质量显著提升
